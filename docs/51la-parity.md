## 第二批：来源、页面、推广链接与 IP

2026-09-14 正在本地验收，尚未部署。新增迁移为 28（站点 IP 排除）、29（页面分组）、30（推广链接与参数字典）；三项已在专用 PostgreSQL 测试库应用。

- 来源分析：按每次访问最早的已记录页面归因，展示类别、来源网站、外部链接、引擎、关键词及引擎交叉表。PV/UV/IP/新访客/访问/跳出/时长分别计算，汇总不相加各行去重值；未知关键词不以 UTM 词替代。仅带 `utm_campaign` 也识别为推广，已识别自然搜索不混入外链。
- 页面分析：完整 URL 默认保留裸查询与锚点，另有路径、标题、入口、退出、域名、页面组视图。停留时间来自下一次真实浏览，无法测量的末页显示未知和覆盖率。最多100组、每组20条规则，重叠组的合计重新去重。
- 推广链接：五项 UTM 参数、字典复用、预览/复制/保存/编辑/删除，保留目的地址原始查询路由和锚点；分析按钮打开对应 UTM 条件。每站点链接和字典各最多500条；编辑字典不会更改已保存链接或历史数据。
- 配置保留：重置统计保留可视化事件规则、页面组、推广链接/字典和 IP 排除规则；删除站点时统一清理，包含软删除。

IP 分析位于 `/websites/:id/ip-addresses`，包含独立 IP、访客、访问、PV、IP 覆盖情况、搜索/排序/分页及 CSV（最多 10,000 行，界面明确标注）。IP 搜索仅筛选明细，顶部汇总独立计算。规则支持 IPv4/IPv6、CIDR 和含端点的起止范围、备注、启停与删除。保留历史数据，重置统计保留配置，删除站点同步删除规则；最多 200 条，并发创建通过站点行锁限制。

普通事件、热力图及录制都在写入前查询主库规则，缓存会话也即时检查；同时校验缓存令牌的用途与站点。原始 IP 与规则不允许通过分享上下文获取，混用登录令牌与分享令牌同样不能越权。敏感表格及 MCP 新签发令牌排除自录制。API 统一 `Cache-Control: no-store`，避免全局配置覆盖接口禁缓存头。

采集入口每次读取主库活动站点策略，软删除、硬删除及录制开关不再受旧缓存或副本影响。`Forwarded` 支持带引号的 IPv4、IPv6及端口，保持原有代理头优先级，不把后续代理地址替代未知首跳。全局只读角色无法更新、删除、转移站点或通过 MCP 写规则；带分享令牌的请求始终遵守分享的报表范围。

已通过真实 PostgreSQL 统计/跨站隔离/规则启停/并发上限验证，以及浏览器 CSV、搜索、规则 CRUD、采集恢复和手机布局验收。ClickHouse 查询实现存在，尚未进行真实 ClickHouse 运行验证。Edge 再次核对 51.LA 的 `/report/setup/datafilter`：智能扫描恶意爬虫属于剩余差距，不能把手工排除规则视为完成全部智能过滤。
